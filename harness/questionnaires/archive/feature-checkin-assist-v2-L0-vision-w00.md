## 背景（出题依据，全部已核实的实测/代码事实）

### 未验证假设（最先暴露，影响多条要点）

- **假设 A（签到通知可达性）**：教师发起签到时若畅课进程已死，系统是否仍弹通知？实测旁证：畅课普通/营销推送走**荣耀厂商通道**（历史通知 `opPkg=com.hihonor.android.pushagent`；APK 组件含 JPush + 荣耀/华为/小米通道插件），进程死后厂商通道仍可投递；但**签到类推送是否同样走通道未实测**（需一次真实签到事件，即 TODO.md 遗留的「开学后校准关键字」）。已尝试实测手段：`dumpsys notification` 历史记录 + `dumpsys package` 组件清单。
- **假设 B（畅课签到 API）**：存在可复用登录态的「进行中签到列表 / 提交签到」HTTP 接口。未抓包、未调研；TronClass 社区有通用逆向资料，但 CHD 部署（畅课 v2.16.0）未验证。**这是轮询/自动签到方向的前置闸门，未验证前不承诺实现。**
- **假设 C（畅课登录态来源）**：畅课是复用学校 CAS 统一认证还是独立账号体系、Web 端域名是什么，未验证（决定轮询方案拿登录态的成本）。

### 真机实测数据点（荣耀 SER-AN00，Android 16 / SDK 36，2026-10-13）

- 畅课 `com.wisdomgarden.trpc` v2.16.0 已安装，targetSdk 35；测试时进程未运行（常态无后台）。
- 本 App `CheckInNotificationListener` **已授权且当前已绑定**（系统 Live listeners 列表内）。
- 本 App **未加电池优化白名单**（`dumpsys deviceidle whitelist` 无本包名）——荣耀省电管控可杀后台。

### 代码事实（Explore 全量扫描 + 文档原文核实）

- 现有链路 = 被动监听畅课通知（`CheckInNotificationListener`，关键字「签到/考勤/点名」+ 15s 防抖）→ `CheckInTriggerCoordinator`（权限门禁 → `LocationSelection` 选位置 → Mock 定位 → 可选拉起畅课）；**对畅课服务器零 HTTP 请求**（`data/remote/` 仅 EAMS/CAS）。
- [ADR-0001](../../../docs/adr/0001-checkin-assist-scope.md) 明确拒绝「解析通知后调用畅课接口完成签到」——本次「伪造请求」诉求触碰该边界，修订与否必须显式拍板。
- 位置编辑器（`LocationEditorSheet.kt`）关联课程/关联教室均为**自由文本**，无课表联动；`CheckInLocation.linkedRoomName` 为单字符串。
- v120/v121 后一门课可挂**多教室**（逗号连接）且分周换教室（线上线下交替）——「多教室 tag」诉求的现实基础。
- 已知系统坑（DESIGN.md §7½）：荣耀 NLS 装机不绑定需手动重开、通知使用权必须手动授权、Mock 定位需开发者选项指定。
- 你的入口校准选择：**侧重监听健壮性**，自动签到作为可选方向保留（风险犹豫中）。

## 决策默认值清单

- [X] **1 问题重定位（单向门，须显式勾选）**：健壮性投资第一优先级 = **本 App 自身的存活与 NLS 绑定**（电池白名单引导、开机拉活监听、NLS 绑定自检重连），而非「畅课不发通知」——因为实测证据显示畅课通知走荣耀厂商通道、畅课进程死后通知大概率仍达，真正断链点在本 App 侧（被杀 + NLS 解绑 + 电池白名单缺失三个实测数据点） 〔实测：opPkg=pushagent + 本机未加白名单 + DESIGN.md 荣耀 NLS 坑〕
- [X] **2 监听主通道仍是 NLS（通知监听）**，不推翻现有 `CheckInNotificationListener`，在其上加固 〔实测证据支持通知可达 + 现有链路已跑通〕
- [X] **3 主动轮询畅课 API 作为第二监听通道进范围，但带前置验证闸**：先实测（抓包/调研）确认假设 B/C 成立，不成立则该通道降级为「不做」并记 OPEN-DECISIONS；验证通过前不写任何轮询代码 〔假设 B/C 未验证；轮询有登录态维护与耗电成本〕
- [X] **4 自动签到（伪造请求完成签到）= 实验性方向保留、默认关（单向门，须显式勾选）**：进 L0 范围的含义仅是「触发源架构上预留 + 用新 ADR 修订 ADR-0001 的对应条款」，**不承诺本期实现**；实现闸门后置到假设 B 抓包验证通过 + 你显式二次确认之后；即便实现也默认关闭、失败静默降级到现有「通知 + Mock」链路——推理：你在入口校准明确「风险犹豫中」，留设计口子不等于开工，把不可逆决策后置到证据齐全时 〔入口校准「侧重监听健壮性」+ ADR-0001 既有边界 + 铁律「AI 不替人决策」〕
- [X] **5 强校验签到永不自动完成**：二维码 / 手势 / 人脸 / 验证码类签到，即便自动签到方向成立也一律排除，只提醒不代签 〔沿用 ADR-0001 第 1 条；技术上是校验对抗，无胜算且性质最重〕
- [X] **6 无障碍服务（AccessibilityService）不进范围**：可监控用户输入的敏感权限、畅课 UI 随版本变动极脆、与轮询方案功能重叠 〔权限成本 + 维护成本；ADR-0001 备选方案表已有类似否决记录〕
- [X] **7 保活策略 = 引导 + 自检，不做对抗系统的黑科技**：电池优化白名单引导 + 荣耀「自启动」开关引导 + `BOOT_COMPLETED` 开机拉活监听 + NLS 绑定自检（`onListenerConnected` / `requestRebind`）自动重连尝试；**不做**双进程互拉 / 1px Activity / 常驻前台服务保命 〔retro 结论「荣耀后台保活是系统层坑，应用层只能引导」+ 个人工具不值得对抗系统〕
- [X] **8 触发源抽象统一**：`CheckInTriggerCoordinator` 升级为「触发源（通知 / 轮询 / 手动 / 未来的自动签到）→ 签到会话级去重 → 响应动作」管线；多通道命中同一签到只响应一次（现有 15s 防抖升级） 〔多通道并存后防重复触发是硬需求；现有 Coordinator 已是 UI/后台共用汇聚点，扩展而非重建〕
- [X] **9 轮询窗口 = 仅课时有窗**：只在当天有课的时段轮询（课前 N 分钟至课后 M 分钟），无课日 / 假期不轮询；N/M/间隔的定值留给 L1 〔省电 + 降低对畅课服务器的请求频率；课表数据本地已有，判窗零成本〕
- [X] **10 UI 重构范围 = 位置编辑器（下拉化 + 课程→教室 tag 联动 + 多教室 tag 增删改）**：签到辅助页其它区块（权限状态区 / 开关区）不动 〔你的原始诉求只点名位置、关联课程、关联教室；小范围可控〕
