## Q1. 核心场景确认：以下 6 个场景哪些是「必须支持」的验收场景？(多选)   [落盘: L0-vision-checkin-assist-v2#核心场景]

- [X] A. **S1 长期未启动后的第一签到**：手机重启或本 App 长期未打开，畅课签到通知经厂商通道到达 → 系统自动拉起监听组件 → 触发管线 → Mock 定位 + 引导通知 —— 这是「畅课和本软件都没启动」的原始痛点场景
- [X] B. **S2 NLS 解绑自检**：荣耀系统更新 / 本 App 装新包后 NLS 未被绑定 → 打开 App 时自检发现并引导重开「通知使用权」—— 系统层行为应用层无法自动修，只能引导
- [X] C. **S3 关键字不命中兜底**：真实签到通知文案不含默认关键字 → 设置页改关键字（现有能力）+ 手机端通知原文记录辅助校准（依赖 Q3 勾选）
- [X] D. **S4 畅课完全静默**：教师发起签到但服务器不推系统通知 → 轮询通道在课时有窗内发现并走同一触发管线 —— 依赖假设 B 验证通过，若轮询不做则本场景降级为「不支持」
- [X] E. **S5 现场快速选位置**：签到提醒已触发，用户点开 App → 位置下拉直选，或按课程匹配 / 记忆自动选
- [X] F. **S6 多教室课命中当周教室**：一门课分周在不同教室（v121 场景）→ 触发时按当前周次实际教室匹配位置（教室 tag 任一命中即命中）

## Q2. 要点 11 衍生——课程下拉「仅当前学期」后，历史学期标定的位置怎么处理？(单选)   [落盘: L0-vision-checkin-assist-v2#范围 + #核心场景]

- [ ] 🤔 我定不了 → 推迟/降风险

## Q3. 手机端测试入口要哪些？(多选)   [落盘: L0-vision-checkin-assist-v2#验收标准(A7) + L2-build 测试入口清单]

出题依据：W00 补充声明新需求「签到窗口短，不一定能马上连接电脑调试，要在手机端留足测试入口」；现有 debug 钩子（shell 包名测试通知）仅 debug 构建可用（`CheckInNotificationMatcher.kt:21`），正式版无任何自助验证手段。

- [ ] A. **畅课通知原文记录器**：NLS 顺手记录最近 N 条畅课通知的渠道 / 标题 / 正文（本地存储 + 页面查看 + 可复制）—— 假设 A 校准与关键字调试的手机端主入口，不连电脑就能拿到真实通知文案
- [ ] B. **端到端通知自检按钮**：正式版内置「发送测试签到通知」（模拟畅课通知格式），验证「通知 → 匹配 → 触发」全链路 —— 把现有 debug-only 钩子升级为正式入口，个人 App 无滥用顾虑
- [ ] C. **NLS 绑定实时验证按钮**：不只显示授权状态（现有权限状态行），点击后发真实 ping 验证 `onNotificationPosted` 回调通不通 —— 直接检测荣耀「授权了但没绑定」坑
- [ ] D. **轮询手动触发按钮**：立即执行一次轮询并展示结果（发现签到 / 未发现 / 登录态失效）—— 依赖轮询通道实现（假设 B 闸门）
