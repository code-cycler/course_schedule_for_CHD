# ADR 0003：签到位置数据模型与触发匹配规则

**状态：** Accepted

## 背景

签到辅助需要持久化用户标定的位置，并在触发时决定使用哪一个位置。需要明确：位置是全局独立还是与课程绑定、触发时如何自动匹配、如何减少用户重复选择。

## 决策

1. **位置为独立记录**，核心字段包括：
   - `id`、`name`（显示名称）
   - `latitude`、`longitude`（WGS-84）
   - `note`（备注）
   - `linkedCourseId`（可选：关联课程标识）
   - `linkedRoomName`（可选：关联教室名）
   - `createdAt`
2. **触发时位置选择规则**：
   - 若只保存了一个位置，直接使用。
   - 否则，按当前课程/教室（从课表获取）匹配 `linkedCourseId` / `linkedRoomName`。
   - 对每一个课程/教室组合，记忆用户上次手动选择的位置；匹配时优先取记忆值。
   - 若仍无法唯一确定，弹出位置选择列表让用户手动确认。
3. **无保存位置时**：弹出通知引导用户先添加位置，点击后进入新增位置页。
4. **Mock 定位精度**：当前阶段全局固定 10 米；`accuracyRadiusMeters` 字段保留为可空占位，未来可改为 per-location 精度。

## 后果

### 正面
- 独立位置模型最简单，可以先做通用 CRUD，后续再逐步加课程关联。
- 可选的课程/教室关联 + 记忆机制，能在不强制用户录入课程的情况下提升自动匹配率。
- 规则清晰、可测试：单位置 → 课程匹配 → 记忆 → 手动选择。

### 负面
- 可选关联使查询和匹配逻辑比纯全局位置略复杂。
- 课程表匹配依赖现有课表数据（`Course` 的 `room` / `name` 等字段）的准确性；若课表未导入或教室名不一致，会 fallback 到手动选择。
- 全局固定精度对需要模拟不同信号强度的场景不够灵活。

## 备选方案

| 方案 | 结果 |
|------|------|
| 位置必须绑定到课程 | **未选**，初期强制绑定会增加录入成本 |
| 位置完全独立，触发时永远手动选 | **未选**，频繁手动选择体验差 |
| 按时间段记忆位置 | **未选**，规则复杂且收益不明显 |
