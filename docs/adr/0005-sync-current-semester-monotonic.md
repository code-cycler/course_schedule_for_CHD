# ADR 0005：同步不得把 currentSemester 打回旧学期（只升不降）

**状态：** Accepted

## 背景

v115 跨学期同步链路出现回归 bug（2026-09-01 用户反馈 + 日志实证）：同步无条件把「当前展示学期」（`currentSemester`）覆盖成教务首页当前显示学期。跨学期窗口（教务系统还没切到新学期）或首页教学周解析失败（回退硬编码 `2024-2025-1`）时，把用户已切到的新学期打回旧学期——「切不回去，直接覆盖」。

日志 `devfiles/chd_schedule_log_20260901_152857.txt`：应用启动 `currentSemester=2024-2025-1`、结束态导航停在 `2024-2025-1`，而 `2026-2027-1` 课表已存在本地。

## 决策

**`currentSemester` 的写入规则 = 只升不降**（用 `startY*2+(n-1)` 单调编码比较）：

- **自动路径**（同步 Step3 / Step3.5 补抓 / banner 获取）：仅当候选学期编码 ≥ 当前编码才写入；候选 < 当前（过渡期，教务未切）**不写**、不动时间线。
- **学期选择器**（用户查看任意学期）：只改导航展示，不写 `currentSemester`（维持现状）。
- **首页教学周解析失败** → 本次同步**中止**：不写任何课表/学期，toast 提示。
- **消灭硬编码 `"2024-2025-1"` 回退**：活动路径 5 处（`LoginViewModel:183`、`AppNavigation:114/141/169`、`LoginUiState:20`）+ 表单登录死代码 4 处。
- **时间线**（`semesterStartDate` / `currentWeek` / `lastParsedWeek`，全局单值）只在候选学期最终成为 currentSemester 时更新，防旧学期周次污染新学期表头（v113 同类坑的镜像）。

## 理由

「同步 = 刷数据」不是「切学期」。用户主动切到的学期是用户主权，不能被同步悄悄覆盖。**只升不降**同时保留「教务已切到新学期时，同步自动带你过去」的便利（对照的「同步完全不动 currentSemester」方案会剥夺这个升级便利，故未选）。解析失败即中止、宁可明确失败也不静默错写两年前的学期 key。

## 后果

### 正面

- 同步永不再把用户打回旧学期（消灭整类回归）。
- 首页解析失败不再错写 `2024-2025-1`；失败可见（toast）。
- 过渡期行为可预期：课表按真实学期入库 + 明确提示「教务仍显示旧学期」。
- `parseHtmlToCourses` 等数据层方法不再越权写「当前学期」状态。

### 负面 / 已知限制

- 候选 < 当前时，同步入库的课表落在教务真实（旧）学期 key——数据按真实学期入库本应如此，不算缺陷。
- 用户故意回看旧学期并同步 → 不会被踢到新学期（特性，不是缺陷）。
- 0 门 toast 在假期可能是常态——「教务尚未发布新学期课表」轻提示可接受。
