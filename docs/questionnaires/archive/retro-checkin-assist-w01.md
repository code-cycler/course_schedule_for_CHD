## 第 4 节 · 学到什么   [落盘: retro 文档#学到什么]

### Q12. 本阶段获得、对未来可复用的经验？（多选 / 开放）   [落盘: retro 文档#学到什么]

- [X]  A. 反射调系统 API 必须**解包 `InvocationTargetException`**，否则真实异常类型被吞
- [X]  B. 第三方/系统 API 的方法名**别信网传**，用 `javap -classpath android.jar` 查 jar 才是真相
- [X]  C. **真机早测**——尤其涉及权限/定位/通知监听，模拟器和单元测试拦不住机型差异
- [X]  D. **增量构建不可信**——真机安装前用 `clean assembleDebug`，并校验 APK 完整性（unzip -l）
- [X]  E. 荣耀/Honor 的 NLS/USB 安装/后台保活是系统层坑，需用户手动操作，应用层只能引导
- [X]  F. 个人项目里「地图选点」往往不如「采集真实位置」——后者更准且免 Key/免坐标转换
- [X]  G. 把边界（不做什么）和合规风险在动手前用 grilling 敲死，比事后删代码省事
- [X]  H. 重大方案反转要落 ADR（哪怕反转两次），未来读者才知道为什么
